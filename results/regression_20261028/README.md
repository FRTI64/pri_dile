## 3. Reactive.F* 修复

`34cb9b0` 的 `_reactive(seed)` 每次调用工厂时继续消耗共享 `random.Random`，导致同一对手的参数随候选数量/顺序变化。修复后参数只在构造时抽样一次。

158 矩阵：3600/3792 行完全一致；192 行差异恰好是 8 个 `Reactive.F*` × 24 候选；其他 family 0 差异。原数据对这 8 类不可复现，固定后的值见 `matchup158_fixed.json`。

9-suite 2048：候选平均分整体下降 **2.4–2.5 分**（固定参数后的正常效应），**Top 8 排名完全不变**；逐 suite 单元最大差 7.27（Neural / complex）。修复版见 `suite2048_fixed.json`。

## 4. catalog 的 VotingPortfolio 差异

24,448 行中 22,475 行完全一致。非 PSRO-Scratch/BR 候选的 差异全部落在 `VotingPortfolio`（每候选 4 个 config，Harvest 6 个）；这是 Plan 3 修复复合规则 RNG 共享 bug 的结果，原 34cb9b0 数据生成于修复前。

PSRO-Scratch 486 行、PSRO-Scratch-BR 395 行差异来自其随机 meta-policy 对对手行为变化的敏感性；当前代码在相同输入下可复现。
